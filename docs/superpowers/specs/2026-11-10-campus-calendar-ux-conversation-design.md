# 校园赛事日历 UI 与对话式新增设计

- 日期：2026-11-10
- 状态：设计获批，规格待用户复核
- 基线：现有 DSH bundle + host/client 半片、本地 JSON store、`/campus-calendar` API、schema version 1
- 视觉方向：B「学生事务工作台」

## 1. 目标

提升日历界面信息层级与阅读效率，减少高频操作等待和不必要重渲染；新增一个 DSH agent tool，让用户在任意 DSH 对话中以自然语言新增竞赛、考试、报名与证书事项。现有月历、筛选、收藏、提醒、CRUD、导入导出与数据可信度规则继续有效。

本次不增加网络抓取、云端同步、OS 通知、模型 API 调用或自动核验。自然语言只由当前 agent 在已获准的会话中理解，工具只负责接收结构化参数、验证并写本地数据。

## 2. 方案比较与决策

1. **独立 DSH 对话工具（采用）**：host half 在 `ctx.tools` 可用的宿主作用域注册工具；agent 将当前对话解析成结构化参数并调用。优点是沿用 DSH 自然对话和权限治理，不在日历里仿造聊天 UI，也不增加第二套模型通道。
2. **插件内对话框**：在日历里做多轮聊天并自行接模型。当前无安全、明确的模型调用边界，会重复 agent UI 与模型能力，增加密钥、权限及错误处理范围，不采用。
3. **仅保留简化表单**：风险最低但不满足自然语言入口诉求，不采用。

## 3. UI 与视觉设计

### 3.1 布局

- 延续侧栏、顶部标题、月历/列表、收藏、事项管理的已有信息架构。
- 采用学生事务工作台：顶部保留月份与档案摘要；主操作收敛到搜索/筛选/视图切换；月历在桌面优先，右侧近期事项强调“下一步”与可信度标签。
- 新增紧凑的“从 DSH 对话添加”提示/命令入口，展示可调用的工具名称和自然语言示例；它只解释入口，不自行提交对话或伪造聊天框。
- 日历格继续只呈现有具体日期的节点。未知日期在议程列表中清楚标为“日期未知”，待确认/预测信息以文字标签补充，不单靠颜色区分。
- 事项编辑改为分组、渐进披露：基本信息、适用范围、来源与核验、关键节点。日常新增的最低必需信息前置；可信度说明和来源约束在相应字段附近展示。仍保留完整编辑能力。
- 窄屏沿用单列结构、图标紧凑导航、月历与议程纵向堆叠、筛选折叠；保持 390px 无横向溢出。

### 3.2 设计令牌与反馈

- 语义色令牌：石墨/冷灰作为文本与边界，青绿作为主操作与已完成状态，暖琥珀作为待确认/预测提示，红色仅用于错误/破坏性动作。保留轻量、低饱和工作台质感，不堆叠卡片、渐变或重阴影。
- 继承当前字体族并建立一致字号、间距、边界和焦点环令牌；支持宿主浅/深主题，不自行强制某一主题。
- 按钮、输入高度和触控间距满足可用尺寸；所有输入有可见 label、错误贴近字段、键盘可达；模态关闭后恢复焦点。
- 过渡只用 transform/opacity，150–220ms，并遵守 `prefers-reduced-motion`。不动画网格尺寸或触发布局回流。

## 4. 对话工具与数据流

### 4.1 工具边界

- 在 host half 的 DSH agent/tool 注册作用域注册工具声明，使用宿主提供的 `tools` 服务及 `@deepseek-ai/dsh-tools` 的 `defineTool` 契约；不在浏览器 client half 注册模型工具。真实桌面联调时按当前宿主版本验证注入名称、tool execute 的 `exec` 类型与取消信号；若目标宿主没有此接口，暂停该条实现并先调整设计，不以浏览器模拟冒充宿主工具。
- 工具名采用稳定、明确的英文标识（计划为 `campus_calendar_add_item`），描述须限定为“新增单个赛事/考试/证书事项”，不得编辑、删除、批量导入或访问外部 URL。
- 工具输入为结构化事项：标题、类别、简介/主办方/适用范围/报名状态、来源 URL 与核验日期、节点列表（类型、日期范围、可信度、说明）。从对话抽取结构由 agent 完成；工具不接受自由文本并自行解析，也不调用模型。
- 工具执行调用 host 内部共享的 `addItem` 业务服务，复用 `validateItem` 和 store；返回规范化事项、可信度结果及明确回执。不得 HTTP 自调用、重复实现校验或绕过原子写入。
- 工具仅新增；写入遵守宿主现有权限、用户 dataDir 与请求取消信号。多条事项、导入、编辑/删除不包含在本次工具范围内。

### 4.2 自动写入与可信度

- 清楚、单一、字段合法的事项在一次工具调用中自动写入，然后向用户返回标题、节点、可信度与本地保存结果。
- 用户说“下月中旬”“快到期”等模糊日期时，不推算具体日期：节点日期保持 `null`，可信度设为 `pending_confirmation`，说明写明“用户描述为……；尚无精确日期/官方来源”。
- 只有用户提供明确日期才写日期；仅当来源 URL 为 http/https 且核验日期真实、节点日期存在时允许 `official_confirmed`。用户提供来源不代表我们已打开或核验它，工具回执不得声称已浏览来源。
- `predicted` 仅能用于用户明确要求记录预测且提供推测依据的情况；不得将模型推断伪装成官方日期。否则待确认或 unknown。
- 标题或类别缺失、日期范围冲突、结构矛盾、同时混入多个事项时工具拒绝此次写入，并要求 agent 追问/拆分；不写部分状态，不静默丢弃输入。
- DSH 工具本身的风险/审批策略遵循宿主注册契约，不另行降低全局权限；此工具只做单项本地新增，删除与覆盖风险不在范围内。

### 4.3 日历 UI 与 API 反馈

- 工具成功写入后，已打开的日历不会依赖后台推送；提供可见“刷新日历”按钮，并在窗口重新聚焦时可做轻量刷新。不得增加隐式轮询。
- 刷新采用可取消的请求序号/AbortController，过期响应不能覆盖较新的状态；用户编辑草稿期间不以服务端状态覆盖表单。
- 新增/收藏/档案保存即时显示 loading/disabled 与成功/失败状态，错误提供可恢复操作。筛选输入节流或 useDeferredValue；纯计算的过滤/日期集合 useMemo，事件处理器保持稳定，避免每次按键重建 42 天网格树。

## 5. 性能与量化验收

- 不增加运行时依赖；保留现有 DSH module-loader 外部 React 的 bundle 方式。
- 对 42 个日历格建立一次月视图模型，并按日期索引节点，避免每格重复全量扫描所有事项/节点；列表及近期待办只在依赖变化时排序/过滤。
- 指标：键入搜索后输入/显示反馈目标 <100ms；本地 1,000 条事项的筛选与构建月格纯计算 p95 <16ms（测试中重复 100 次采样）；React 更新范围通过 profiler/渲染计数验证，搜索一次只允许日历内容区域更新，不触发 profile、侧栏等子树无关重绘；前后构建压缩体积增加不超过 10% 且不加依赖。
- 所有异步按钮在 100ms 内提供忙碌反馈；请求失败显示原因和重试/恢复入口。
- 记录测试环境、事项数量、采样方式及中位数/p95；不宣称真实硬件帧率，除非用浏览器性能轨迹实测。

## 6. 模块边界与文件预期

- `src/host.js`：host half 注入 DSH tools 服务，注册定义和执行入口；继续保留现有 HTTP route 与 authorization。
- `src/host/store.js`：增加单进程串行化的读-校验-追加-原子写服务；UI 的新增 POST 与 agent tool 共用同一 mutation，避免两个请求各自读到旧快照后互相覆盖。编辑/删除/导入仍走现有写入路径，本次明确只保证新增路径的并发追加不丢记录。
- 新增领域服务（建议 `src/domain/create-item.js`）：对新增 payload 规范化、可信度规则与错误组装；若现有 model 校验足够，则不做冗余抽象。
- `src/client.js`、`src/styles.css`：工作台视觉、分组编辑、手动刷新/焦点刷新、过滤与日期索引性能优化、a11y 状态反馈。
- `test/host.test.js`：工具注册（若 host tools 测试环境可用）、成功写入、模糊日期 null、官方确认约束、无效输入拒绝、并发新增不丢失及写入错误。
- `test/client.test.js`、`test/layout.test.js`：回归现有流程、新布局交互、取消/错误状态、刷新期间保留草稿、明暗主题与 reduced-motion。
- README 与 progress 台账：记录工具使用语义、可信度规则、测试指标和未解决的真实 DSH 联调事项。

## 7. 错误处理、隐私和安全

- 只写入 `$DSH_HOME/campus-events-calendar/state.json`，不发送记录到模型之外的服务、不抓取来源 URL、不上传对话历史。
- request/body 与条数仍限制在当前上限；工具单次只接收一项；字符串、URL、日期、数组与枚举走既有领域验证。
- 拒绝重复/空标题、无效日期、倒置日期范围、来源协议非 http(s)、官方确认无来源/核验日期/具体日期、预测无依据、演示项目标官方等状态。
- 错误分为工具参数错误、校验错误、磁盘读写错误、权限拒绝；对用户返回人话，不暴露路径以外的堆栈或宿主秘密。

## 8. 验收与测试

1. 月历工作台在 1280px 下有稳定的月历与下一步事项层次；在 390px 下无横向溢出，窄屏导航/筛选/事件行可操作。
2. 明暗主题下文字和控件具有足够对比度；Tab/Enter/Escape 路径完整，reduced-motion 关闭装饰动画。
3. 对话“我报名校赛，下月中旬截止”生成单一校赛事项，日期 `null`、可信度 `pending_confirmation`，回执说明未猜日期。
4. 对话提供具体日期但无来源时可新增 unknown/pending 记录，不得标 official；来源+核验日期+具体日期齐备才可保存 official。
5. 缺标题/类别、多个事项、冲突日期不写入，并返回 agent 可用的追问/拒绝结果。
6. 写入后刷新/窗口聚焦可见新项；刷新不能覆盖本地未提交草稿，旧请求不覆盖新状态。
7. 性能基准按第 5 节重复测试；现有 `node --test test/*.test.js`、`npm run build`、`npm pack --dry-run` 全通过。
8. 在真实 DSH desktop runtime 执行工具注册和调用联调；未获用户明确要求前不安装/启用到现有 profile、不重启宿主。若无真实 runtime 联调条件，必须明确标注 gap。
