# 轻量赛事日历与结构化事项设计

## 目标

以用户参考的独立月历为视觉和操作基准：月历与选中日赛事/考试详情是主任务。选中日期后可在右侧快速新增结构化赛事事项；这不是通用备忘录，名称、节点类型、等级和短描述均服务于赛事/证书日历。已有赛事、证书和专业维护能力保留。避免首次进入被建议、资料档案、筛选和长时间轴挤占主界面。对于有稳定历届月份规律的年度赛事/考试，应积极提供月份级预测并标明依据，不将预测冒充官方日期。

## 主视图

- 月历占主要宽度，右侧/下方详情显示所选日期及其事项。
- 默认展示当前月；点日期选中并更新详情，点上下月日期时切换月份；保留已有月份导航。
- 赛事/证书及兼容的旧 memo 均可在日期格以事项色块标识；赛事保留按节点时间窗铺格与等级色，年份精度不铺格。
- 默认主视图不展示生成建议、档案引导、覆盖缺口提示、搜索/多条件筛选和优先时间轴；仍可从独立的管理入口访问已有收藏、数据维护、Agent 建议与筛选/时间轴/列表能力（不删除功能）。

## 当天赛事事项

- 选中日期后，详情侧栏内嵌「新增赛事 / 考试事项」短表单，不用弹窗。字段：日期（预填所选日）、事项名称、节点类型（如报名截止、比赛、考试、提交、结果）、重要等级和简短描述。
- 新事项以普通 `competition` 或 `certificate` item 写入现有 `/items` API；单日日期来源于用户输入但未附官方凭证时标 `pending_confirmation`，不得自动标成 `official_confirmed`。
- 保存后即时更新当天详情和月历。旧 `memo` 数据/API 继续读取、导入和维护，作为兼容路径，不再是新增主流程或通用文本产品。

## 数据与隔离

- 既有 `memo` category 和 `/memos` 窄 API 保持兼容，确保旧数据不丢；新建事项走 `/items`，不引入另一套数据模型。
- 新事项归入 competition / certificate，按节点 type 与类别校验，参与现有适配、列表、ICS 和导入导出。

## 视觉方向

参考图一的浅色月历：白色纸面与细线格、月历为第一视觉、日期数字清楚、选中日蓝色描边、今日蓝色圆点；事件按等级用低饱和浅蓝/浅橙/柔红整格底色，事件标题为轻量小标记；右侧当天详情简洁、原生表单、分割线。保持现有品牌深青侧栏，但减少主内容区域的容器层级、说明文案和重复入口。窄屏转为月历在上、详情在下。

## 错误与验证

- 标题空白、非法日期、超长标题在客户端阻止；后端再次校验并回 400，UI 展示错误且保留输入。
- 旧 memo API 仍限制只编辑/删除 memo；普通赛事 id 不能通过 memo endpoint 修改或删除。
- 测试覆盖默认月历简化、日期预填、typed event 经 `/items` 保存后即时显示、预测规则不改已有日期且幂等、旧 memo 与赛事数据/ICS 不回归。
- 验收：build、完整 test suite；浏览器截图检查主月历与侧栏新增赛事事项，桌面与窄屏均检查。
